## 2.1.2 (2026-10-13)

### Security

- 2.1.1's dependency overrides did not apply to global installs: users got
  `protobufjs` 7.5.4 (critical) and `@grpc/grpc-js` 1.12.6 (high). 2.1.2
  ships an `npm-shrinkwrap.json` that pins the patched versions
  (`protobufjs` 7.6.6, `@grpc/grpc-js` 1.13.6). The audit gate now audits
  a real install of the packed tarball.
- The shrinkwrap also leaves out `react-native`, which npm used to install
  as a peer of a module the SDK only loads on React Native, and `metro`
  and the unpatched `braces` with it. A global install goes from 429
  packages to 226.
- How the gate works: `npm run audit:prod` packs the tarball, installs it
  globally into a temp prefix through a local stand-in registry, and runs
  `npm audit --omit=dev --audit-level=high` on what is on disk. The
  stand-in registry is needed because npm ignores a shrinkwrap when it
  installs from a tarball file; it honours one only when the registry
  reports it, as npmjs.org does for a published package.
- Apps generated by `apix add` are not affected by any of this: the
  overrides are written into the app's own `package.json`, where npm
  applies them. They still get `react-native` through the SDK.

### Changed

- The CLI no longer calls itself "enterprise". `apix --help` now says "Add
  working Hedera integrations to your Next.js app", and the descriptions
  of `chat`, `recommend`, `explain` and `compare`, the `--verbose` banner
  and the messages of `generate` say plainly what each one does. No
  command, flag or behaviour changed.
- CI: `actions/checkout`, `actions/setup-node` and
  `actions/upload-artifact` v4 -> v7, and `gitleaks/gitleaks-action` v2 ->
  v3, in the three workflows (they run on Node 24; the old ones ran on the
  deprecated Node 20).
- `npm run proof:testnet` can run against an installed copy of APIX
  (`APIX_PROOF_ROOT=<its directory>`) instead of this repository's sources.

## 2.1.1 (2026-10-12)

Security fixes, Vite wallet fix, post-release docs.

### Security

Advisories published after 2.1.0 put 2 critical and 9 high findings in
`npm audit --omit=dev`. In the tree a user installs, peer-only packages
left out, this release brings that back to 0 critical and 0 high (4
moderate and 7 low remain, as in 2.1.0).

> **Correction (2.1.2):** that claim was wrong for users. The gate behind it
> applied APIX's `overrides`, which npm ignores when APIX is installed
> globally. A global install of 2.1.1 gets `protobufjs` 7.5.4 (critical) and
> `@grpc/grpc-js` 1.12.6 (high): 1 critical and 12 high in all, counting
> `braces` and the packages that depend on it. The same applies to the
> `@grpc/grpc-js` 1.13.6 fix listed under 2.1.0. Fixed in 2.1.2.

- `handlebars` 4.7.9 -> 4.7.10, and APIX now requires `^4.7.10`. Fixes
  three critical advisories: GHSA-xw65-4hp5-5hc7, GHSA-8r5x-fm3f-whwj and
  GHSA-p8wg-vrv2-v86f. The rendered templates are byte-identical.
- `shell-quote` 1.10.0 -> 1.12.0 in the lockfile (critical,
  GHSA-pqg4-j6r4-53mv). A fresh install already resolves to 1.12.0.
- `braces` (high, GHSA-vfj7-8cjw-p6xm) is **not fixed**: 3.0.3, the latest
  version, is affected and there is no patched one, so no upgrade or
  override helps.
  - In what users install, `braces` only comes through a peer dependency:
    `@hashgraph/sdk` -> `@hashgraph/cryptography` ->
    `react-native-get-random-values` declares `react-native` as a peer,
    and npm installs peers automatically, with `metro`, `micromatch` and
    `braces` behind it. APIX never loads `react-native` in Node.
  - In this repository it also comes through development tools (`jest`,
    `nodemon`), which are not part of the published package.
  - `npm audit --omit=dev` on this repository therefore still reports 9
    high findings, all of them `braces` and the packages that depend on it.
- The CI audit gate now audits the user's install tree instead of the
  repository's: `npm run audit:prod` (scripts/audit-prod.mjs) resolves
  APIX's `dependencies` and `overrides` fresh, as
  `npm install -g apix-hedera` does, and runs
  `npm audit --omit=dev --omit=peer --audit-level=high` on it. Peer-only packages are left out for the reason above. `npm audit
  --omit=dev` on the repository still runs in CI, without blocking.

### Fixed

- The experimental React/Vite `wallet` integration failed `tsc` in a fresh
  Vite app: the generated `wallet-service.ts` had five unused imports and
  one unused parameter, which Vite's `noUnusedLocals` and
  `noUnusedParameters` reject.

### Changed

- Package published as apix-hedera; repository moved to
  github.com/tdeu/apix. The command is still `apix`.
- README.md and docs/getting-started.md no longer say that 2.1.0 is
  unpublished, and the Discord placeholder is gone from the README.
- This changelog dates 2.1.0 and lists the `@grpc/grpc-js` 1.13.6 fix that
  shipped in it.
- BACKLOG.md and docs/REVIVAL_2.1.md describe the state after the release,
  and docs/TESTNET_PROOF.md records the testnet check of the grpc-js fix.

### Known issues

- `braces` 3.0.3 (high, GHSA-vfj7-8cjw-p6xm, no patched version) is
  installed next to APIX, and next to every app generated by `apix add`,
  through the SDK's `react-native` peer dependency. `npm audit` reports it
  there.
- `npm audit` on the development dependencies (jest, solc and others)
  reports high advisories. They are not part of the published package.

Both are tracked in [BACKLOG.md](BACKLOG.md).

## 2.1.0 (2026-09-30)

The revival release. Every Hedera operation APIX performs or generates was
run on testnet and verified on the mirror node
([docs/TESTNET_PROOF.md](docs/TESTNET_PROOF.md)).

### Added

- `apix add consensus` (alias `hcs`) generates a working HCS integration:
  topic and message routes with input checks.
- `apix add` checks support before writing anything. Next.js (App Router,
  TypeScript) is supported, React/Vite with TypeScript gets `wallet` only
  (experimental), and everything else is refused with a message.
- `apix add` never overwrites a file that differs from what it would
  generate unless you pass `--force`. A failed add (including a failed
  `npm install`, whose own output is shown) leaves the project exactly as it
  was.
- `apix create-token`: `--max-supply`, and HashScan links for the token and
  the transaction.
- Mainnet confirmation: `create-token` and `add hts --create-token` ask
  before spending HBAR on mainnet; `--yes` skips the question, and with no
  terminal they refuse without it.
- Library (`hedera-operations`): `mintToken`, `queryContract` (decoded
  view-function results), and ABI-encoded arguments for contract calls and
  constructors.
- A shared AI provider: Anthropic or OpenAI, with the models set in one
  place and overridable (`APIX_ANTHROPIC_MODEL`,
  `APIX_ANTHROPIC_FAST_MODEL`, `APIX_OPENAI_MODEL`).
- `apix health` reports by area; `--strict` exits 1 unless every area is ok.
- `npm run proof:testnet` (testnet proof script), a nightly testnet smoke
  workflow, a generation e2e harness (`npm run e2e:generate`) run in CI, and
  CI for build, lint, tests and `npm audit`.
- Docs: getting started, commands, integrations, troubleshooting,
  CONTRIBUTING, and the testnet evidence with observed fees.

### Changed

- Generated code installs, type-checks and builds in a fresh Next.js app.
  It follows the project's layout (with or without `src/`) with relative
  imports, generates every module it imports, and matches
  `@hashgraph/sdk` 2.80 (generated projects get `~2.80.0`: the tested
  version or a patch of it, never an untested minor).
- Generated server modules import `server-only` and create the Hedera
  client on first use, so the private key stays on the server and
  `next build` needs no credentials. The operator signs every transaction;
  a connected wallet is only shown and used as a transfer recipient.
- Generated token creation uses an INFINITE supply unless `maxSupply` is
  given.
- Token creation in the CLI and library uses APIX's own
  TokenCreateTransaction: initial supply in the smallest unit, and key flags
  that set the operator key. Every operation takes its IDs from the
  network's receipt.
- `apix generate` classifies the requirement with the AI, then writes the
  same files as `apix add`.
- `compose` is experimental: hidden from `--help` unless
  `APIX_EXPERIMENTAL=1`, and it runs only with `--experimental`.
- The wallet component is `ConnectWallet` (`components/ConnectWallet.tsx`),
  not to be confused with the WalletConnect protocol.
- Default AI models: `claude-sonnet-5` (Anthropic), `gpt-4o-mini` (OpenAI,
  unverified).
- Hackathon-era documents moved to `docs/archive/`.

### Removed

- The test-account fallback, simulation leftovers, mock data and canned AI
  replies. Commands fail with a clear error instead.
- `apix deploy` (it submitted no transaction).
- `validate --enterprise/--performance/--security/--compliance/--testnet/--mainnet/--files`
  and `create-token --testnet/--mainnet`: they did nothing. The network comes
  from `HEDERA_NETWORK`.
- 28 more flags that no code path read:
  - `add --provider/--type`;
  - `generate --regulation/--business-context/--business-goals/--integration-type/--framework/--custom-logic/--validate-live`;
  - `recommend --business-goals/--current-systems/--regulations/--budget/--timeline/--interactive`;
  - `explain --detailed/--examples/--regulations`;
  - `compare --use-case/--criteria`;
  - `confidence --industry/--complexity`;
  - `debug --files/--logs/--suggest-fixes`;
  - `compose --templates/--novel-pattern/--validate-live`.

  Also the global `--json` (output was not JSON), `--log-file` (the path
  was never used) and `--no-file-logging` (never took effect).
- The error-recovery "retry", which decided outcomes at random. `apix debug`
  is diagnosis only.
- Groq, telemetry and every other variable APIX doesn't read from
  `.env.example`; each remaining variable has a one-line comment.
- Hackathon-era dev scripts: `scripts/setup-apix.js` (a v1 bootstrap that
  overwrote package.json), `demo-verify.js`, `test-workflow.js` (superseded
  by the e2e harness) and `test-all-apix.sh` (ran every command unattended,
  including token creation).
- Hard-coded contract bytecode and the fake contract deploy.
- hedera-agent-kit and LangChain (`@langchain/core`, `@langchain/anthropic`,
  `@langchain/openai`): nothing needed them once token creation used the
  SDK directly, and APIX's prompt templates are its own few lines of code.
  This removed 10 of the 21 production audit advisories and about 195
  production packages.
- Unused dependencies: `@hashgraph/hedera-wallet-snap`,
  `@walletconnect/sign-client`, `@walletconnect/utils`, `qrcode-terminal`,
  `axios`, `lodash`, `lru-cache`, `terminal-kit`, `tsconfig-paths` and their
  `@types` packages.
- Dead code that no command reached: APIX's own wallet-connection service
  (`src/services/wallet-integration.ts`), performance and security
  "managers", a second file generator, a template verifier, 17 planner
  methods and 13 package-manager methods nothing called, and 12 templates no
  integration renders. The generated files are byte-identical.
- The testnet IDs published with the hackathon submission, which were never
  created.

### Fixed

- Token creation through hedera-agent-kit reported success without a token
  ID and ignored the requested supply and keys. Tokens are now created with
  the SDK, and the kit was removed.
- `callSmartContract` sent no function data, so calls reverted.
- Generated token creation without `maxSupply` failed with
  `INVALID_TOKEN_MAX_SUPPLY`.
- Next steps after `apix add` list only what was generated.
- HashScan links point to the right page for tokens, topics, contracts,
  accounts and transactions.
- `compose` read `--requirement` while the flag is `--requirements`.

### Security

- Secrets are masked (first 6 characters at most) in console output, log
  files, `apix logs` / `apix last-error` and every CLI error message.
- Hedera inputs are validated before any network call, and the Hedera
  client is closed when the credentials are invalid.
- Vulnerable dependencies were upgraded or overridden: no critical or high
  advisories in production dependencies on the release date
  (`npm audit --omit=dev`). Upgrades: `@hashgraph/sdk` 2.80.0, with
  `protobufjs` and `@grpc/grpc-js` overridden (without the overrides, a
  critical and two high advisories return).
- `@grpc/grpc-js` is overridden to 1.13.6. `@hashgraph/sdk` pins 1.12.6,
  which has two high-severity advisories (GHSA-m9gg-hp2v-232j,
  GHSA-f596-whhp-79r4), and the earlier 1.12.7 override was still affected.
  Generated apps get the same overrides (`@grpc/grpc-js` 1.13.6,
  `protobufjs` 7.6.6) in their `package.json` before install, so they don't
  resolve the vulnerable versions either.
- CI runs gitleaks, and the `.env.example` API key exposed in October 2025
  was removed (see `docs/archive/SECURITY_INCIDENT_REPORT.md`).
